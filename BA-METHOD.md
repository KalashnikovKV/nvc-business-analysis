# Как устроен бизнес-анализ

## Разделение документов

| Документ | Вопрос | Содержание |
|----------|--------|------------|
| **BRD** | Зачем? | Проблема, цели, стейкхолдеры, границы, риски, критерии успеха |
| **PRD** | Что? | Персоны, сценарии, user stories с критериями приёмки, приоритеты, схемы экранов |
| **ТЗ** | Как? | Числовые пороги, тестовые случаи, API, поставка, покрытие тестами |

Этот пакет — BRD и PRD. Пороги качества в нём те же, что в ТЗ, но записаны словами продукта; полные таблицы и контракты остаются в ТЗ.

## Правила

1. Стейкхолдеры — все, кто влияет на продукт или кого он задевает: пользователи, владелец продукта и команда, платформы, стандарты, регуляторы, хостинг, конкуренты, сообщества, люди вокруг съёмки. Пользователи — одна из групп. Роли в работе с продуктом (кто снимает, собирает, забирает пакет) описываются в персонах.
2. Проблема описывается через боль конкретных сегментов пользователей и понятна человеку без технического фона. Альтернативы — через обзор рынка с источниками и честное сравнение.
3. Язык — продуктовый. Ссылки на эпики, истории, KPI и NFR идут по их ID (US-2.4, KPI-1), чтобы работала трассировка.
4. Приоритеты Must / Should / Could / Won't относятся к текущему релизу.
5. Если что-то расходится с ТЗ, исправляется пакет, а не ТЗ.
6. Факты и числа из внешних источников — только со ссылкой `[@ключ]` на источник из `references.json`. Сборка нумерует источники по IEEE в порядке первого упоминания: [3], [2]–[5]. Каждый источник списка цитируется хотя бы раз — иначе сборка падает.
7. Истории в разделе 2.5 записываются строками таблиц по эпикам. Приложение 1, сводный файл, сайт и DOCX собирает `scripts/build-ba.py`, их вручную не правят.
8. Объём основного текста — 15–20 страниц: введение 1–2, глава 1 6–8, глава 2 8–10. Диаграммы в полный размер — в приложении 2.

## Структура

Структура повторяет требования к блоку бизнес-анализа (2026/27): `00` введение → `01` глава 1, аналитическая часть → `02` глава 2, требования к системе → `03` список литературы → `04` приложение 1, бэклог → `05` приложение 2, диаграммы → `06` заявления → `wireframes/` (сайт и макеты).
