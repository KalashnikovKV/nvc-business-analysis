# 02. Стейкхолдеры, границы, альтернативы

## 2.1 Стейкхолдеры

| Роль | Зачем им продукт | Influence | Interest | Что требуют |
|------|------------------|-----------|----------|-------------|
| Оператор съёмки | Снять участок и понять, годится ли запись | Высокое | Высокое | Зона на экране, preflight, понятный отказ |
| Сборщик карты | Получить карту и проверить до передачи в игру | Высокое | Высокое | Загрузка, статус, отчёт, ходьба в браузере |
| Разработчик игры | Импортировать визуал и коллизию без ручной доводки | Среднее | Высокое | Пакет из пяти файлов, meters / Y-up, без rescale |
| Владелец сервиса / эксплуатация | Стабильные прогоны, безопасные секреты, повторный деплой | Среднее | Среднее | Контейнер, конфиг, логи, хранилище, URL |
| Люди в кадре / владелец места | Не попасть в материалы | Низкое на backlog | Высокое на этику | Без лиц крупным планом; съёмка пола/стола/макета |

```text
                    Interest →
                 Low                 High
           ┌───────────────────┬───────────────────┐
  High     │                   │ Оператор          │
Influence  │                   │ Сборщик           │
           ├───────────────────┼───────────────────┤
  Medium   │ Владелец сервиса  │ Разраб. игры      │
           ├───────────────────┼───────────────────┤
  Low      │                   │ Люди в кадре      │
           └───────────────────┴───────────────────┘
```

## 2.2 Границы релиза

### Входит

- Съёмка с LiDAR, подсказки зоны и обхода, проверка записи  
- Сборка пакета карты в размерах датчика + отчёт  
- API, очередь заданий, хранение метаданных и файлов пакета  
- Веб: загрузка бандла, список заданий, отчёт, ходьба + исходный кадр  
- Открытый контракт API, контейнер без секретов, публичный URL  

### Не входит

- Rescale под конкретного персонажа внутри пайплайна  
- Полноценная игра и обязательный Unreal  
- Обучение собственной модели глубины  
- Android как основная платформа съёмки  

## 2.3 Допущения

1. Для качественной съёмки есть телефон с LiDAR.  
2. Карту можно проверить по сохранённому бандлу в браузере — телефон не обязателен каждому проверяющему.  
3. Сервис доступен по обычному URL.  
4. Оператор и сборщик могут быть одним человеком.  
5. Разработчик игры умеет импортировать GLB.

## 2.4 Ограничения

1. Стартовая платформа съёмки — iOS / iPadOS + LiDAR.  
2. Зона по умолчанию 80×80 см (настраивается; больше = дороже по compute).  
3. Пайплайн не меняет масштаб геометрии под персонажа.  
4. Форматы: glTF/GLB, ARKit, LiDAR.  
5. Код — на английском.

## 2.5 Альтернативы

| Вариант | Плюс | Минус для нашего продукта |
|---------|------|---------------------------|
| RealityScan / Meshroom + Blender | Знакомый путь к мешу | Нет одного пакета visual+collision+report и сервиса быстрой проверки |
| Только монокулярная глубина | Не нужен LiDAR | Нет надёжных размеров в метрах датчика; только резерв |
| Polycam / KIRI | Быстрый скан | Чужой закрытый контракт; нет нашей коллизии и отчёта |
| RoomPlan / скан комнаты | Быстрый layout | Другая задача: комната, не игровой patch ~80×80 см |

**Выбор:** LiDAR-съёмка → свой пайплайн → пакет GLB → проверка коллизии в браузере.  
**Почему:** контролируемый контракт (визуал, коллизия, метрики, явный отказ) и проверка проходимости без установки движка.
