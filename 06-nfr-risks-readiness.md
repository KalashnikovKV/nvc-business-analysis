# 06. NFR, риски, готовность продукта

## 6.1 Нефункциональные требования

| ID | Требование | Как проверить |
|----|------------|---------------|
| NFR-1 | Повтор с новым ключом идемпотентности: тот же метод, треугольники в пределах 15% | Два отчёта |
| NFR-2 | Код на английском | Review |
| NFR-3 | Секреты не в репозитории и не в образе; в тестах нет лиц крупным планом | CI + ревью бандлов |
| NFR-4 | Проверка карты не требует игрового движка | Ходьба в браузере |
| NFR-5 | Параметры прогона в конфиге и воспроизводимы | Повторный прогон |
| NFR-6 | Публичный URL; подъём из контейнера | Live URL + IaC |

## 6.2 Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Меш неузнаваем | Высокое | Малая зона, обязательные позы, отказ вместо мусора |
| Нет телефона с LiDAR у части пользователей проверки | Высокое | Сохранённые эталонные бандлы; проверка в браузере |
| Тяжёлая сборка на большой зоне | Среднее | Зона 80×80 по умолчанию; лимиты кадров и точек |
| Случайный rescale ломает «метры датчика» | Высокое | Запрет gameplay-rescale; в манифесте только centering |
| Обрыв upload без статуса | Среднее | Idempotency + явный error/retry |

Отказ preflight при плохой съёмке — нормальный сценарий, не риск.

**Зависимости:** LiDAR-устройство для съёмки; хостинг; эталонные бандлы; образ со стеком реконструкции.

## 6.3 Данные и этика

- Тестовые съёмки: пол / стол / макет, без лиц крупным планом.  
- Секреты — в env хостинга.  
- В БД — задания, метрики, ссылки на файлы.  
- На старте нет пользовательских аккаунтов с ПДн (доступ по API-ключу).

## 6.4 Готовность продукта

Релиз считается готовым, когда:

1. Оператор проходит съёмку с понятным preflight.  
2. Сборщик загружает бандл, видит отчёт и проходит по коллизии в браузере.  
3. Разработчик игры получает пакет в meters / Y-up без rescale.  
4. Плохой вход даёт отказ с причиной, без геометрической заглушки.  
5. Выполнены KPI-1…KPI-4 и NFR-1…NFR-6.

Детальные числовые бюджеты меша, набор эталонных бандлов и контракт API — в техническом задании.
