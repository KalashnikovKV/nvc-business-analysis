# Appendix 1. Backlog

The full table of epics and stories is given in Table A.1.1.

Table A.1.1. Backlog: epics and stories

| ID | Epic | Story | Acceptance criteria | MoSCoW |
|----|------|-------|---------------------|--------|
| US-1.1 | E1 | **Recording the zone.** **As a** capture operator, **I want** to record an area on a phone with LiDAR **so that** I get a capture with depth in metres. | 1) **Given** a phone with LiDAR and the camera tracking its position, **when** the operator starts recording, **then** a 0.8 × 0.8 m zone is fixed on the floor. 2) **Given** the recording has stopped, **when** the capture is saved, **then** it contains video, camera poses, metadata and depth frames. 3) **Given** the camera is not yet tracking its position, **when** the operator tries to start recording, **then** the "Record" button is disabled and the hint "AR is starting — move the camera slowly over the floor" is shown. 4) **Given** recording has run for 30 s, **when** the time is up, **then** recording stops automatically. | Must |
| US-1.2 | E1 | **Recording check before upload.** **As a** capture operator, **I want** to know at once whether the recording is usable **so that** I do not send a defective capture and can retake it on the spot. | 1) **Given** a recording of 10–30 s, a camera path ≥ 0.28 m, a view-angle change ≥ 90°, a zone width ≤ 0.92 m and a gap between poses ≤ 0.5 s, **when** the check finishes, **then** "Map ready" and the "Send" button are shown. 2) **Given** a recording shorter than 10 s, **when** the check finishes, **then** "The recording must last 10 to 30 seconds" is shown. 3) **Given** a camera path shorter than 0.28 m, **when** the check finishes, **then** "Walk around the zone" is shown. 4) **Given** a view-angle change under 90°, **when** the check finishes, **then** "The views are too similar — walk around and show all sides" is shown. 5) **Given** a zone wider than 0.92 m, **when** the check finishes, **then** "The zone is too large — capture an area of about 80×80 cm" is shown. 6) **Given** a gap between poses longer than 0.5 s, **when** the check finishes, **then** "The gap between frames is too large — retake more smoothly" is shown. 7) **Given** any check has failed, **when** the operator views the result, **then** only "Retake" is available instead of "Send". | Must |
| US-1.3 | E1 | **Walk-around hint.** **As a** capture operator, **I want** to see during recording how much more to walk **so that** I capture the area on the first attempt. | 1) **Given** recording has run for 5 s or more, **when** the camera path is shorter than 0.28 m, **then** the hint "Don't stand still — walk slowly around the zone" is shown. | Should |
| US-2.1 | E2 | **Upload from the phone.** **As a** capture operator, **I want** to send the recording to the server with one button **so that** the build starts without a manual command. | 1) **Given** the check has passed, **when** the operator taps "Send", **then** a job with the status "queued" is created. 2) **Given** the upload failed because of the network, **when** the error arrives, **then** the reason is shown as text and the upload can be repeated. 3) **Given** a job for this capture already exists, **when** the operator sends the same capture again after a network error, **then** the same job is returned and no second build starts. 4) **Given** the user already has three builds running, **when** they send another capture, **then** no job is created and "Wait for the current builds to finish: there are already three" is shown. | Must |
| US-2.2 | E2 | **Upload from the browser.** **As a** map builder, **I want** to upload a saved capture through a browser form **so that** I can build a map without a phone. | 1) **Given** the upload form is open, **when** a file without video, poses or metadata is selected, **then** the missing parts are shown before sending. 2) **Given** the capture is complete, **when** the builder submits the form, **then** a job is created and the job list opens. 3) **Given** the file is larger than 400 MB, **when** the builder submits the form, **then** no job is created and "The capture file is larger than 400 MB" is shown. | Must |
| US-2.3 | E2 | **My jobs in the browser.** **As a** map builder, **I want** to open all my jobs in the browser with one button on the phone **so that** I can view reports and maps on a large screen. | 1) **Given** the user has jobs, **when** they tap "Open in browser", **then** the browser opens a list of all their jobs with date and status. 2) **Given** the one-time link has already been opened or more than 10 minutes have passed, **when** it is opened again, **then** the list does not open and "The link has already been opened or has expired" is shown. 3) **Given** another browser without a session, **when** the address of someone else's job is opened, **then** the map and report are not shown and "A link from the phone or a test link is required" is shown. | Must |
| US-2.4 | E2 | **Status filter.** **As a** map builder, **I want** to filter jobs by status **so that** I quickly find ready maps and rejections. | 1) **Given** the job list is open, **when** the "ready" filter is selected, **then** only ready jobs are shown. | Should |
| US-2.5 | E2 | **Deleting a capture from the phone.** **As a** capture operator, **I want** to delete an unneeded capture from "My maps" **so that** I free up phone storage. | 1) **Given** a capture card in "My maps", **when** the operator confirms deletion, **then** the capture files are deleted from the phone. | Could |
| US-3.1 | E3 | **Build report.** **As a** map builder, **I want** the report to show the status, reconstruction method and metrics **so that** I decide by numbers rather than by eye. | 1) **Given** the build succeeded, **when** the builder opens the report, **then** the status "ready", the reconstruction method "LiDAR depth fusion", the triangle counts of the visual and collision meshes and the file sizes are shown. 2) **Given** the build was rejected, **when** the builder opens the report, **then** instead of metrics the status "rejected" and the reason text from Table 2.10 are shown. | Must |
| US-3.2 | E3 | **Rejection with a reason.** **As a** map builder, **I want** an unsuitable capture to be rejected with a clear reason **so that** I do not mistake a defect for a map. | 1) **Given** the capture violates any condition in Table 2.10, **when** the build finishes, **then** the job status is "rejected" and the reason is the text from the same row of Table 2.10. 2) **Given** the status is "rejected", **when** the builder opens the job, **then** no placeholder geometry is delivered, and viewing and download are unavailable. 3) **Given** the capture meets all conditions in Table 2.10, **when** the build finishes, **then** the status is "ready" and there is no rejection. | Must |
| US-3.3 | E3 | **Map within the game budget.** **As a** game developer, **I want** to receive the map within budget **so that** I do not simplify it by hand. | 1) **Given** the reconstructed surface exceeds the budget, **when** the build runs, **then** the system itself simplifies the visual mesh to 50,000 triangles and the collision mesh to 25% of the visual mesh faces. 2) **Given** the build succeeded, **when** the package is written, **then** the visual mesh is ≤ 50,000 triangles and ≤ 25 MB, and the collision mesh is ≥ 100 faces and ≤ 8 MB. 3) **Given** the budget is still not met after simplification, for example the collision mesh has fewer than 100 faces or the visual mesh file is larger than 25 MB, **when** the build finishes, **then** the status is "rejected" with the reason "The map did not fit the game budget; no package was issued". | Must |
| US-3.4 | E3 | **Comparing a repeated build.** **As a** map builder, **I want** to compare a repeated build of the same capture with the first one **so that** I can confirm the result is reproducible. | 1) **Given** two builds of the same capture, **when** the builder compares the reports, **then** the reconstruction method is the same and the triangle counts differ by no more than 15%. | Should |
| US-4.1 | E4 | **Walking the map.** **As a** map builder, **I want** to walk a character on the finished map in the browser **so that** I check walkability without a game engine. | 1) **Given** the build succeeded, **when** the builder opens the viewer, **then** the character stands on the collision mesh for at least 5 s and does not fall through. 2) **Given** the viewer is open, **when** the builder moves the character along the zone diagonal from one corner to the opposite corner (about 1.1 m), **then** the character completes the route without falling through or getting stuck. 3) **Given** the build was rejected or is still running, **when** the builder opens the viewer, **then** the map does not load, and the job status and the rejection reason, if any, are shown. | Must |
| US-4.2 | E4 | **Capture frame next to the map.** **As a** map builder, **I want** to see a capture frame next to the model **so that** I can compare the map with the real place. | 1) **Given** the viewer is open, **when** the map has loaded, **then** a capture frame from the same camera is shown next to it. 2) **Given** another browser without a session, **when** the address of a frame of someone else's job is opened, **then** the frame is not served. | Must |
| US-4.3 | E4 | **Character height in the viewer.** **As a** map builder, **I want** to change the character height in the viewer **so that** I can try the map for different games. | 1) **Given** the viewer is open, **when** the builder changes the character height, **then** the character changes, while the map geometry and the package files do not. | Should |
| US-5.1 | E5 | **Package download.** **As a** game developer, **I want** to download a five-file package **so that** I can open the map in my engine. | 1) **Given** the build succeeded, **when** the developer clicks "Download", **then** they receive `map.glb`, `collision.glb`, `manifest.json`, `bounds.json`, `report.json`. 2) **Given** the package has been downloaded, **when** both GLB files are opened in a glTF viewer, **then** they open without errors. 3) **Given** the job is still queued, building or rejected, **when** the developer requests the package, **then** no files are served and "A package exists only for a ready job" is shown. | Must |
| US-5.2 | E5 | **Real scale and package description.** **As a** game developer, **I want** to receive the map in sensor metres with an axis description **so that** I can set the character scale myself. | 1) **Given** the package has been downloaded, **when** the developer reads the manifest, **then** it states metres, Y up, the fact of centring and a scale of 1. 2) **Given** the package has been built, **when** the map and capture sizes are compared, **then** the geometry scale has not changed. 3) **Given** the manifest units are not metres or the scale is not 1, **when** the package is checked, **then** the package is not issued. | Must |
| US-5.3 | E5 | **Godot instructions.** **As a** game developer, **I want** short instructions on opening the package in Godot **so that** I do not have to figure out the import myself. | 1) **Given** the report is open, **when** the developer follows the "How to open in Godot" link, **then** the steps for importing the visual and collision meshes are shown. | Should |
| US-6.1 | E6 | **Test link to the reference jobs.** **As** the service team, **we want** to issue a reusable link to four reference jobs **so that** the product can be checked without a LiDAR phone. | 1) **Given** a test link has been issued, **when** it is opened in any browser, **then** only the four reference jobs with reports and walking are shown. 2) **Given** the test link is open, **when** the list is viewed, **then** users' personal jobs are not shown. 3) **Given** the test link is open, **when** someone tries to upload a new capture, **then** no job is created and "The test link only allows viewing the reference jobs" is shown. | Must |
| US-6.2 | E6 | **Replacing the test link.** **As** the service team, **we want** to replace the test link **so that** access via the old one is closed. | 1) **Given** the link has been replaced, **when** the new one is opened, **then** the four reference jobs are shown. 2) **Given** the link has been replaced, **when** the old one is opened, **then** the jobs do not open and "A link from the phone or a test link is required" is shown. | Must |
